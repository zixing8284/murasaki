# Standalone docs site

@murasaki/react98 will move component documentation and examples to a standalone Nextra/Next.js docs site, and the Windows 98 playground will embed that built site in an iframe instead of owning a separate documentation system. This supersedes ADR 0006: the markdown-first playground docs implementation introduced generated `.md.live.ts` sidecars, custom transform complexity, heavier Shiki-driven chunks, and live demo behavior that did not justify the maintenance cost.

## Consequences

- The standalone docs site becomes the source of truth for component reference, examples, navigation, and search.
- Playground documentation becomes an embedded docs window that points at the built docs artifact.
- Live examples should be maintained as ordinary React/TSX modules or explicit imports, not generated from markdown code fences.
- Nextra may provide the docs shell, but it should not recreate the discarded live-demo compiler path.
- Static preview must use a basePath-aware server for `/programs/docs/`; `next start` is not valid with `output: 'export'`.
- Search is generated by Pagefind during `pnpm docs:build` and written to `packages/docs/out/_pagefind`.

## Implemented scope

- Create a new `packages/docs` package; keep `packages/next-fixture` as a compatibility fixture.
- Use Nextra Docs Theme with light customization, not a fully custom Windows 98 docs theme.
- Build the docs site for the `/programs/docs` base path and copy its static export into `packages/playground/public/programs/docs` for iframe embedding.
- Use webpack for the first docs production build path while Nextra and Next 16 Turbopack compatibility remains uneven.
- Migrate all public component pages with live examples, source strings, accessibility notes, and SSR guidance.
- Use MDX pages that import TSX example modules; show source with explicit source strings, not raw generated sidecars.
- Validate with `pnpm ui:build`, `pnpm docs:build`, `pnpm docs:preview`, `pnpm docs:embed`, `pnpm play:build`, and `pnpm lint`.
